# 路线图与验收

## 1. 版本路线

### V0：数据底座

接通自部署 Forecast、Historical、Elevation、Geocoding，建立关注点、区域、数据源和质量状态；完成单位、时区、缓存、原始快照和 API 日志。

### V1：气象工作台

完成气象总览、Cesium 空间指挥台、预报与模型、风光资源评估、基础风险规则和天气简报导出。

### V2：风险与报告闭环

增加多模型和集合对比、历史回看、情景推演、风险复盘、质量事件工单、分享链接和权限审计。

### V3：扩展数据与智能分析

在确认数据来源和产品边界后，再评估负荷、电价、储能或新能源设备数据。新增能力必须建立独立的数据模型和版本，不回写 V0.2 的天气资源语义。

## 2. 验收标准

- 新建关注点后，输入坐标即可获取时区、海拔和天气预报；页面显示数据时间和质量状态。
- Cesium 选中关注点后，右侧同时看到当前天气、选中变量趋势和未关闭风险事件。
- 预报页面可对比至少两个模型，显示模型运行时间、集合范围和变量单位。
- 资源页面可生成太阳能或风能评估，并说明区域、统计周期、数据模型和质量状态。
- 风险事件包含触发条件、证据变量、数据时间、影响区域、当前状态和处理记录。
- 数据断流时在阈值内标记过期或降级；恢复后自动补采并更新覆盖率和质量结果。
- 报告可以追溯到天气 run、关注点/区域、规则版本和分析版本。
- UI 页面遵循统一导航、Token、状态颜色和布局规则；过期、缺失、降级状态直接可见。

## 3. 开发顺序

1. 先实现数据源适配、标准化 schema、质量状态和关注点管理。
2. 再实现总览与预报页面，打通时间序列查询和模型对比。
3. 接入 Cesium 图层和空间查询，保证视口加载和时间轴联动。
4. 实现风光资源评估和风险规则，补齐证据链。
5. 最后实现情景、报告、分享和审计，并用真实接口数据替换样例数据。

## 4. 质量门槛

- 所有接口响应带数据时间、来源和质量状态。
- 采集任务幂等、可重试，失败可定位到模型、区域、变量和 run。
- 页面不展示未标注来源的样例结论。
- 视觉稿、功能文档和 API 命名必须使用同一套导航与模块名称。
